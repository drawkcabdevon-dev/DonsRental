# Google Sheets Formula/Command Injection via customerEmail

**ID:** vuln-0003
**Severity:** HIGH
**Found:** 2026-08-27 19:50:59 UTC
**Target:** https://rentals.onlineverywhere.com
**Endpoint:** /api/bookings
**Method:** POST
**CWE:** CWE-94
**CVSS:** 7.3
**Fix Effort:** Medium

## Description

The /api/bookings endpoint is vulnerable to potential Google Sheets formula or command injection via the customerEmail parameter. When special characters or formula-like payloads are submitted, the server responds with a 500 Internal Server Error, indicating a backend processing issue due to improper input sanitization.

## Evidence

## Impact

Successful exploitation could lead to data manipulation, exfiltration of sensitive booking information from Google Sheets, or potentially command execution on the backend system if the injection vector is used in a shell context.

## Technical Analysis

The customerEmail parameter appears to be processed by a backend component that interacts with Google Sheets. When payloads containing SQL-like syntax or Google Sheets formulas are submitted, the server consistently returns a 500 Internal Server Error. This indicates a failure to properly sanitize or validate user input before it is processed by the backend system, leading to a potential injection vulnerability.

## Proof of Concept

1. Intercept a legitimate POST request to /api/bookings.
2. Modify the customerEmail field with a SQL injection payload (e.g., ' OR 1=1--@example.com').
3. Send the modified request and observe a 500 Internal Server Error.
4. Repeat with a Google Sheets formula injection payload (e.g., '=HYPERLINK("http://evil.com")@example.com').
5. Observe another 500 Internal Server Error.

## Remediation

Implement robust server-side input validation and sanitization for all user-supplied data, especially for fields that interact with backend systems like Google Sheets. Ensure that special characters are properly escaped or encoded, and that input conforms to expected formats (e.g., valid email address regex). If using Google Sheets formulas, explicitly disable formula parsing for user-supplied data or use secure methods to write data.

## Assumptions

The application uses customerEmail directly in Google Sheets operations without proper sanitization.
